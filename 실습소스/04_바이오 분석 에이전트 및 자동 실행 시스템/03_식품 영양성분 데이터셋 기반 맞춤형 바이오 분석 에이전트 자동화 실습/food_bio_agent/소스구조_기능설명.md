# 식품 영양성분 RAG + Tool Calling 바이오 분석 에이전트  
## 소스 구조 및 기능 상세 설명

> 교육용 시스템입니다. 의료 진단·치료·개인 생체반응 예측 목적이 아닙니다.

---

## 1. 시스템 개요

본 프로젝트는 식품의약품안전처 **식품영양성분 DB** 로컬 파일 3종을 기반으로,

1. 문서 전처리 → 임베딩 → **ChromaDB** 저장  
2. **Retriever(RAG)** 로 관련 식품 정보 검색  
3. **LangChain Agent Tool Calling** 으로 정량 조회·비교·계산·추천  
4. **Streamlit** UI 및 **Markdown/TXT 리포트** 자동 생성  

까지 이어지는 맞춤형 식품 영양 분석 파이프라인을 구현합니다.

### 사용 데이터

| 데이터 유형 | 원본 예시 | 역할 |
|------------|-----------|------|
| 건강기능식품 | `*건강기능식품DB*.xlsx` | 기능성 제품 등록 정보·영양수치 |
| 음식 | `*음식DB*.xlsx` | 조리·급식 등 음식 영양정보 |
| 가공식품 | `*가공식품DB*.xlsx` | 시판 가공식품 영양정보(대용량) |

세 데이터는 **하나로 합치지 않고** 유형별로 관리합니다.  
RAG에는 유형별 샘플 문서를 넣고, **정확한 수치 계산·필터링은 전체 Parquet 원본**을 Pandas 도구로 처리합니다.

## 3. 전체 아키텍처·데이터 흐름

```text
[사용자 질문] ──► Streamlit(app.py) / CLI(agent.py)
                        │
                        ▼
              ┌──── Agent(run_agent) ────┐
              │  도구 선택·호출           │
              └──────────┬───────────────┘
         ┌───────────────┼────────────────┬──────────────┐
         ▼               ▼                ▼              ▼
   rag_food_search  nutrient_lookup  compare/calc   recommend
   (rag.py+Chroma)  (Pandas 전체DB)   (Pandas)       (필터링)
         │
         ▼
   ingest.py ←── data_loader.py ←── data/*.xlsx
   (문서·임베딩)     (Parquet 캐시)

최종 출력: 화면 답변 + reports/*.md + agent_demo_log.json
```

### RAG vs 정량 도구 구분

| 구분 | 용도 | 근거 |
|------|------|------|
| RAG 검색 | 설명·관련 식품 문서 찾기 | Chroma 유사도 검색 문서 |
| Pandas 도구 | 수치 조회·비교·섭취량 계산·조건 추천 | 원본 Parquet 컬럼 값 |

문서에 없는 효능·수치를 추측하지 않으며, 없는 값은 0으로 채우지 않습니다.

## 4. 모듈별 상세 설명

### 4.1 `config.py` — 설정·환경변수

**역할**

- 프로젝트 경로, 데이터셋 파일 패턴, 핵심 영양성분 컬럼명 정의
- API 키를 **`C:\env\.env`** 에서만 로드

**주요 항목**

| 심볼 | 설명 |
|------|------|
| `ENV_FILE` | 기본 `C:\env\.env` (`FOOD_BIO_ENV_FILE`로 변경 가능) |
| `load_env()` | dotenv 로드 |
| `get_openai_api_key()` | `OPENAI_API_KEY` 반환(따옴표 제거) |
| `DATA_DIR` / `PARQUET_DIR` / `REPORT_DIR` | 데이터·캐시·리포트 경로 |
| `CHROMA_DIR` | 기본 `C:\MyCursorLab\chroma_food_bio_agent` (한글 경로 HNSW 오류 회피) |
| `DATASET_SPECS` | 유형별 glob, 제공량 컬럼 후보, 텍스트 메타 컬럼 |
| `CORE_NUTRIENTS` | 에너지·단백질·당류·나트륨 등 핵심 영양 컬럼 |
| `RAG_SAMPLE_LIMITS` | RAG 문서화 시 유형별 최대 샘플 수 |

**의존**: 거의 모든 모듈이 import 시점에 `config`를 통해 환경변수를 선로드합니다.

### 4.2 `data_loader.py` — 데이터 로딩·탐색

**역할**

- Excel 원본을 읽어 **Parquet** 으로 캐시(대용량 가공식품 DB 재로딩 가속)
- 데이터 탐색 요약(`explore_summary.json`) 저장
- 식품명 스마트 검색

**주요 함수**

| 함수 | 기능 |
|------|------|
| `find_excel(data_type)` | glob으로 유형별 xlsx 경로 탐색 |
| `ensure_parquet()` | 최초 1회 Excel→Parquet 변환 |
| `load_dataset()` / `load_all()` | 유형별 또는 전체 DataFrame 로드 |
| `available_nutrients()` | 실제 존재하는 핵심 영양 컬럼만 반환 |
| `serving_column()` | 기준 제공량 컬럼명 탐색 |
| `explore_dataset()` / `save_explore_report()` | 행·열·결측·샘플 식품명 요약 |
| `get_food_row()` | 식품명 검색(정확일치 > 대표토큰 > 접두 > 부분일치) |
| `to_numeric_series()` | 영양값 숫자 변환(`errors='coerce'`) |

**부가 컬럼**

변환 시 `_data_type`, `_source_file` 을 붙여 출처를 유지합니다.

---

### 4.3 `ingest.py` — 문서 전처리·임베딩·ChromaDB

**역할**

- 각 행을 검색 가능한 `Document` 로 변환
- 임베딩 생성 후 Chroma 컬렉션에 영속 저장
- 임베딩 백엔드/차원 변경 시 **자동 재구축**

**문서 변환 (`row_to_document`)**

문서에 포함하는 정보(데이터에 있는 값만):

- 식품명, 데이터 유형, 데이터구분명
- 제조사·대표식품·분류 등 텍스트 메타
- 기준 제공량
- 등록된 핵심 영양성분 수치

빈 식품명·의미 없는 행은 제외합니다. 존재하지 않는 효능 문구는 생성하지 않습니다.

**임베딩 (`get_embeddings`)**

| 조건 | 백엔드 | 모델 | 차원 |
|------|--------|------|------|
| `OPENAI_API_KEY` 있음 | OpenAI | `text-embedding-3-small` | 1536 |
| 키 없음 | HuggingFace | `paraphrase-multilingual-MiniLM-L12-v2` | 384 |

`embedding_meta.json`에 backend/model/dimension을 기록하고,  
이전 DB와 차원이 다르면(예: 384→1536) 자동으로 Chroma를 지우고 다시 구축합니다.

**주요 함수**

| 함수 | 기능 |
|------|------|
| `build_documents()` | 유형별 샘플링 후 Document 리스트 생성 |
| `build_vectorstore(rebuild=False)` | Chroma 구축/재사용 |
| `sample_search()` | 구축 후 스모크 검색 |

**CLI**

```bash
python ingest.py --rebuild        # 강제 재구축
python ingest.py --explore-only   # 탐색만
```

### 4.4 `rag.py` — Retriever / RAG 답변

**역할**

- Chroma Retriever로 유사 문서 top-k 검색
- 검색 문맥만으로 LLM 답변(또는 키 없을 때 문서 원문 요약)

**주요 함수**

| 함수 | 기능 |
|------|------|
| `get_retriever()` | top-k, 선택적 `data_type` 필터 |
| `retrieve_docs()` | 식품명·출처·본문 dict 리스트 |
| `answer_with_rag()` | 프롬프트 규칙 적용 후 답변 dict |

**프롬프트 규칙 요약**

1. 검색 문서에 있는 정보만 사용  
2. 없는 수치·효능·치료 효과 단정 금지  
3. 식품명·출처 명시  
4. 결과 없으면 정보 부족 고지  
5. 의료 목적 아님 명시  

**반환 구조**

```json
{
  "question": "...",
  "answer": "...",
  "sources": [{"food_name","data_type","source","food_id"}],
  "mode": "llm" | "extractive" | "empty"
}
```

### 4.5 `tools.py` — Agent Tool Calling 도구 6종

LangChain `@tool` 데코레이터로 정의되며, Agent가 질문에 맞게 선택·호출합니다.

| 도구명 | 입력(요약) | 기능 |
|--------|------------|------|
| `rag_food_search` | query, data_type, top_k | RAG 문서 검색 |
| `nutrient_lookup` | food_name, data_type, nutrients | Pandas 정밀 영양 조회 |
| `compare_nutrients` | food_names(쉼표), nutrients | 여러 식품 공통 항목 비교 |
| `calculate_intake` | food_name, amount, unit, nutrient | 기준 제공량 대비 섭취량 비례 계산 |
| `recommend_foods` | data_type, min_protein, max_sugar, max_energy, max_sodium | 조건 필터 추천 |
| `generate_analysis_report` | title, content, fmt | MD/TXT 리포트 저장 |

**공통 정책**

- JSON 문자열로 결과 반환(Agent·로그 파싱 용이)
- 없는 영양값은 `null` (0 가정 금지)
- 기준 단위(g/ml 등)가 다르면 환산하지 않고 실패 메시지
- 추천 시 알레르기 안전성 보장 불가 disclaimer 포함

`ALL_TOOLS` 리스트에 모아 `agent.py`에 전달합니다.

### 4.6 `agent.py` — Agent 오케스트레이션

**역할**

사용자 자연어 질문을 받아 도구를 선택·호출하고 최종 답변을 만듭니다.

**실행 모드**

| 모드 | 조건 | 동작 |
|------|------|------|
| LangChain Agent | `C:\env\.env`에 OpenAI 키 있음 | `create_agent` 또는 `create_react_agent` |
| 규칙 기반 라우터 | 키 없음 또는 Agent 실패 | 키워드로 도구 직접 호출(데모/오프라인) |

**규칙 라우터 매핑 예**

| 질문 키워드 | 호출 도구 |
|-------------|-----------|
| 추천 | `recommend_foods` + `rag_food_search` |
| 비교 | `compare_nutrients` |
| 계산 / NNg | `rag_food_search` + `calculate_intake` |
| 보고/리포트/저장 | `recommend_foods` + `generate_analysis_report` |
| 그 외 | `rag_food_search` (+ 따옴표 식품명 시 lookup) |

**주요 함수**

- `run_agent(question)` — 통합 진입점  
- `run_langchain_agent(question)` — OpenAI Tool Calling  
- `_rule_based_route(question)` — 로컬 폴백  
- `demo_scenarios()` — 과제 시나리오 A~F 일괄 실행

## 7. 실행 방법

```bash
cd food_bio_agent
pip install -r requirements.txt

# 1) 데이터 캐시(최초 Excel→Parquet, 가공식품은 시간 소요)
python data_loader.py

# 2) Chroma 구축(임베딩 변경 시 --rebuild)
python ingest.py --rebuild

# 3) UI
streamlit run app.py

# 또는 전체 데모
python run_pipeline.py
python agent.py --demo
```

임베딩 백엔드를 바꾸면(로컬↔OpenAI) 차원 불일치가 나므로,  
코드가 메타를 보고 자동 재구축하거나 `python ingest.py --rebuild`를 실행합니다.  
Streamlit을 이미 띄운 상태라면 **재시작**이 필요합니다.

## 10. 설계 시 유의·예외 처리 요약

1. **단위 혼용 금지**: 기준 제공량이 `100ml`인데 입력이 `150g`이면 계산 거부  
2. **임베딩 차원 일치**: 384(local) ↔ 1536(OpenAI) 혼용 시 자동/수동 재구축  
3. **식품명 매칭**: 부분일치 노이즈를 줄이기 위해 정확·토큰·접두 우선 순위  
4. **대용량 가공식품**: Excel 직접 반복 로드 대신 Parquet 캐시  
5. **Windows 한글 경로**: Chroma는 ASCII 경로(`CHROMA_DIR`)에 저장  
6. **의료 면책**: UI·리포트·프롬프트에 교육용임을 명시

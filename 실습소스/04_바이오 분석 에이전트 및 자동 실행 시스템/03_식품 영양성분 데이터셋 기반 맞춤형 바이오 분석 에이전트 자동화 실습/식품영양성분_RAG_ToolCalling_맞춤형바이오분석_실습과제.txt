식품 영양성분 데이터셋 기반 맞춤형 바이오 분석 에이전트 자동화 실습 과제
(RAG + Tool Calling 통합)

1.  과제 개요

식품의약품안전처 식품영양성분 DB에서 다운로드한 로컬 데이터 파일 3개를
활용하여, RAG 검색과 AI Agent Tool Calling을 결합한 맞춤형 식품 영양
분석 서비스를 개발한다.

사용할 데이터 파일은 다음과 같다. - 가공식품 DB - 음식 DB - 건강기능식품
DB

세 파일은 사전에 다운로드하여 프로젝트의 data 폴더에 저장한다.
실습에서는 Open API를 호출하지 않고 로컬 파일을 사용한다. 파일명,
시트명, 컬럼명은 데이터 버전에 따라 다를 수 있으므로, 실제 파일을 확인한
뒤 코드에서 경로와 컬럼 매핑을 설정한다.

최종 시스템은 사용자의 자연어 질문을 분석하여 RAG 검색 도구, 영양성분
검색 도구, 영양 계산 도구 등을 선택적으로 호출하고, 검색 결과와 계산
근거를 포함한 분석 결과를 생성한다.

2.  개발 목표

-   로컬 CSV·Excel 데이터를 Python으로 로딩하고 구조를 분석한다.
-   텍스트형 정보를 전처리하여 임베딩을 생성한다.
-   ChromaDB에 문서와 임베딩을 저장한다.
-   Retriever로 질문과 관련된 문서를 검색하는 RAG 파이프라인을 구현한다.
-   LangChain Agent가 RAG 검색 도구와 Python 기반 영양 분석 도구를
    호출하도록 구현한다.
-   식품 영양성분 검색, 비교, 맞춤형 추천, 섭취량 계산을 수행한다.
-   결과를 Streamlit 화면과 Markdown/TXT 리포트로 제공한다.

3.  데이터 준비

프로젝트 폴더 예시:

food_bio_agent/ app.py ingest.py rag.py tools.py report.py data/
가공식품_DB_파일 음식_DB_파일 건강기능식품_DB_파일 chroma_db/
requirements.txt README.md

실제 파일명과 확장자는 다운로드한 원본에 맞게 유지한다. ChromaDB 저장
폴더는 임베딩 구축 후 생성한다. 데이터 파일을 무조건 하나의 테이블로
합치지 말고, 데이터 유형별로 구분하여 관리한다.

4.  필수 구현 단계

단계 1. 로컬 데이터 로딩 및 탐색 - Pandas로 세 데이터 파일을 읽는다. -
CSV, XLSX 등 실제 형식에 맞는 로딩 함수를 사용한다. - 파일별 행·열 수,
컬럼명, 상위 5개 행, 결측치를 확인한다. - 텍스트, 식품명, 성분명, 설명
등 RAG 문서에 활용할 수 있는 컬럼을 찾는다. - 영양성분 수치와 단위가
있는 컬럼은 별도 분석용으로 보존한다.

단계 2. 문서 전처리 - 각 데이터 행을 검색 가능한 문서로 변환한다. -
문서에는 식품명, 데이터 유형, 주요 설명 및 실제 제공되는 영양성분 정보를
포함한다. - 문서 메타데이터에 데이터 출처, 식품 ID 또는 행 식별자,
데이터 유형을 저장한다. - 빈 식품명이나 의미 있는 내용이 없는 행은
제외한다. - 중복 문서와 불필요한 공백을 정리한다. - 지나치게 긴 텍스트는
적절한 크기로 분할한다. - 데이터에 존재하지 않는 설명이나 건강 효능을
만들어 넣지 않는다.

단계 3. 임베딩 생성 - 전처리된 문서를 임베딩 모델로 벡터화한다. - 예:
OpenAI Embeddings를 사용한다. - API 키는 환경변수(C:/env/.env)에서 읽고 코드에 직접
기록하지 않는다. - API 기반 임베딩을 사용하지 않는 환경에서는 로컬
임베딩 모델로 대체할 수 있다. - 임베딩 모델과 데이터 버전을 기록하여
재현성을 확보한다.

단계 4. ChromaDB 저장 - 문서, 임베딩, 메타데이터를 ChromaDB 컬렉션에
저장한다. - 로컬 영속 저장을 설정하여 프로그램을 재실행해도 벡터 DB를
재사용할 수 있도록 한다. - 데이터가 갱신되었을 때 기존 컬렉션과 중복
저장되지 않도록 ID와 재구축 절차를 설계한다. - 저장된 문서 수와 샘플
검색 결과를 확인한다.

단계 5. 검색 Retriever 구성 - ChromaDB에서 Retriever를 생성한다. -
사용자 질문과 유사한 문서를 검색한다. - 검색 개수(top-k)를 설정하고 검색
결과에 식품명과 출처 메타데이터를 포함한다. - 검색 결과가 없거나
관련성이 낮으면 정보가 부족하다고 응답하도록 처리한다. - 검색된 문서가
질문에 실제로 답하는지 확인할 수 있도록 출처를 표시한다.

단계 6. RAG 질의응답 구성 - 사용자의 질문을 입력받는다. - Retriever로
관련 문서를 검색한다. - 검색 문맥을 LLM에 전달하여 문서에 근거한 답변을
생성한다. - 답변에 사용된 식품명과 데이터 출처를 표시한다. - 검색 결과에
없는 영양 수치나 건강 효능은 추측하지 않도록 프롬프트를 작성한다.

단계 7. Agent Tool Calling 구성 다음 기능을 각각 도구로 분리한다.

1)  RAG 식품 정보 검색 도구: Retriever를 통해 관련 식품·성분 정보를
    검색한다.
2)  영양성분 정밀 검색 도구: Pandas로 식품명과 영양성분 값을 조회한다.
3)  영양성분 비교 도구: 선택한 식품들의 공통 영양 항목을 비교한다.
4)  섭취량 계산 도구: 기준 제공량과 사용자가 입력한 양에 맞춰 섭취
    영양소를 계산한다.
5)  맞춤형 추천 도구: 사용자가 지정한 열량·단백질·당류·나트륨 조건으로
    후보를 필터링한다.
6)  리포트 생성 도구: 검색·비교·계산 결과를 Markdown 또는 TXT로
    저장한다.

LangChain의 create_agent() 등 현재 버전에 맞는 Agent 구성 방식을
사용한다. 사용자의 질문에 따라 Agent가 필요한 도구를 선택하고 호출하도록
한다. 최종 답변에는 데이터 근거, 계산 조건, 추천 이유를 포함한다.

단계 8. 맞춤형 식품 추천 - 예: ‘단백질이 높고 당류가 낮은 가공식품을
추천해줘.’ - 데이터에 실제로 존재하는 영양 항목과 값으로 필터링한다. -
기준 단위와 비교 조건을 표시한다. - 추천 결과에 식품명, 주요 영양성분,
추천 근거를 제공한다. - 알레르기 정보가 실제 데이터에 없으면 알레르기
안전성을 보장할 수 없다고 안내한다.

단계 9. 시각화 및 리포트 자동화 - Streamlit으로 검색어, 추천 조건, 식품
선택 화면을 만든다. - 영양성분 비교 결과를 표와 막대그래프로 표시한다. -
분석 결과를 Markdown 또는 TXT 파일로 저장한다. - 리포트에는 질문, 검색된
식품, 근거 데이터, 영양 계산 결과, 추천 기준, 데이터 한계를 포함한다.

5.  사용자 시나리오

시나리오 A. RAG 검색 사용자: ‘이 제품에 어떤 영양성분 정보가 등록되어
있어?’ 시스템: 관련 문서를 Retriever로 검색하고 출처와 함께 요약한다.

시나리오 B. Tool Calling 기반 영양성분 비교 사용자: ‘식품 A와 식품 B의
열량, 단백질, 당류, 나트륨을 비교해줘.’ 시스템: Agent가 영양성분 검색 및
비교 도구를 호출해 실제 수치가 포함된 표를 만든다.

시나리오 C. RAG + 계산 도구 사용자: ‘이 식품의 영양정보를 설명하고
150g을 먹으면 단백질을 얼마나 섭취하는지 계산해줘.’ 시스템: RAG 도구로
식품 정보를 검색하고 계산 도구로 섭취량에 따른 값을 산출한다.

시나리오 D. 맞춤형 추천 사용자: ‘당류가 낮고 단백질이 높은 가공식품을
추천해줘.’ 시스템: Agent가 추천 도구를 호출해 조건에 맞는 식품을 찾고,
RAG 검색 결과를 이용해 관련 정보를 설명한다.

시나리오 E. 건강기능식품 정보 확인 사용자: ‘이 건강기능식품의 DB 등록
정보를 알려줘.’ 시스템: 건강기능식품 DB의 관련 문서를 검색하고 실제로
제공되는 정보만 정리한다. 질병 예방이나 치료 효과를 임의로 단정하지
않는다.

시나리오 F. 자동 리포트 사용자: ‘오늘 비교한 식품의 영양 분석 결과를
보고서로 저장해줘.’ 시스템: Agent가 필요한 검색·계산 도구를 호출하고,
결과를 Markdown 또는 TXT 리포트로 저장한다.

6.  기술 요구사항

-   Python
-   Pandas, NumPy
-   LangChain Agent 및 Tool Calling
-   ChromaDB
-   LangChain의 Chroma 통합 패키지 및 OpenAI 통합 패키지 또는 선택한
    대체 모델 패키지
-   임베딩 모델
-   Streamlit
-   Matplotlib 또는 Plotly
-   CSV/Excel 파일 처리 라이브러리
-   환경변수 기반 API 키 관리

실제 설치 패키지와 import 경로는 사용 중인 LangChain 버전에 맞춘다.
OpenAI API를 이용하는 경우 임베딩과 LLM 호출에 인터넷 연결 및 API 사용
권한이 필요하다. 로컬 데이터 조회 자체에는 식품 DB API 키가 필요하지
않다.

9.  유의사항

-   데이터 컬럼명과 단위는 다운로드한 실제 파일에서 확인한다.
-   데이터에 없는 값은 임의로 생성하거나 0으로 간주하지 않는다.
-   서로 다른 기준 단위의 영양성분을 직접 비교하지 않는다.
-   RAG 검색 결과와 정량 계산 결과를 구분한다. 문서 검색은 설명과 관련
    정보 검색에 사용하고, 정확한 수치 계산은 원본 데이터 기반 Python
    도구를 사용한다.
-   검색 결과가 없거나 불충분하면 그 사실을 명시한다.
-   API 키는 환경변수로 관리하고 소스 코드나 제출물에 포함하지 않는다.
-   이 실습은 교육용 데이터 검색 및 영양 분석 시스템이다. 의료 진단,
    질병 치료 또는 개인의 생체 반응 예측을 목적으로 하지 않는다.

10. 최종 과제 목표

가공식품 DB, 음식 DB, 건강기능식품 DB를 로컬에 저장하고, 문서 전처리 →
임베딩 → ChromaDB 저장 → Retriever 검색 → RAG 질의응답 → Agent Tool
Calling → 영양 분석 및 계산 → 자동 리포트 생성으로 이어지는 전체
파이프라인을 구현한다.

사용자가 자연어로 질문하면 AI Agent가 RAG 검색 도구와 영양 분석 도구를
적절히 선택하여 호출하고, 실제 데이터에 근거한 맞춤형 식품 영양 분석
결과를 제공하는 서비스를 완성한다.
